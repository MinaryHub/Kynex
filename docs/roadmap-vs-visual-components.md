# KYNEX 로드맵: Visual Components 대체

작성일: 2026-10-14 · 기준: KYNEX `6c19cd1` 이후의 작업 트리(로봇 자세 조작, 프로그램, URScript, 충돌 검사까지)

Visual Components(이하 VC)는 공장 레이아웃, 공정 시뮬레이션, 로봇 오프라인 프로그래밍(OLP)을
한 제품군으로 파는 대표적인 상용 도구입니다. 이 문서는 KYNEX의 현재 기능을 VC와 나란히 놓고,
VC를 대체하기 위해 무엇을 어떤 순서로 만들지 정리합니다. VC 기능은 공개 자료 기준이며, 출처는
맨 아래에 있습니다.

## 정해진 방향 (2026-10-14)

| 결정 | 계획에 미치는 영향 |
|---|---|
| 목표는 VC **대체** | VC 사용자가 KYNEX만으로 같은 일을 끝낼 수 있어야 함. 공장 물류까지 범위에 포함 |
| 첫 대상은 **CNC 공정 자동화** | 첫 이정표(M1)를 CNC 머신 텐딩 셀로 정함(4절). 그리퍼, CNC 장비 모델, 신호 연동, 팔레트 격자, 장비 가동률이 최우선. 용접용 CAD 경로 생성은 뒤로 |
| **유료 시뮬레이터는 쓰지 않음** | 포스트프로세서는 무료 시뮬레이터가 있는 곳은 그것으로, 없는 곳은 기준 출력 비교와 실제 로봇 시험으로 검증(7절) |
| **KYNEX만 개발**, Kreate는 별도로 진행 | Kreate에 변경을 요청하는 항목은 계획에서 뺌. Kreate는 지금 기능 그대로(장면 모델링, URDF 가져오기, 공동 편집 세션) 쓰고, 컴포넌트 정의 같은 것은 KYNEX가 자체 셀 파일에 둠(8절) |

## 요약

- **로봇 셀 하나의 OLP는 뼈대가 섰습니다.** IK, MoveJ/MoveL 경로, 사이클타임, 충돌 검사,
  URScript가 동작합니다.
- **CNC 머신 텐딩 셀을 끝까지 시뮬레이션하는 것이 1단계입니다.** 소재를 팔레트에서 집어 CNC에
  넣고, 가공을 기다려 완성품을 빼내 배출하는 반복을 신호로 맞물려 재생하고, 사이클타임과 장비
  가동률을 보여 주는 것까지입니다. VC로 하던 머신 텐딩 검토를 KYNEX로 할 수 있게 되면 M1입니다.
- **그다음은 OLP의 폭(제조사, 명령, CAD 경로), 카탈로그·레이아웃, 가상 시운전, 공장 물류 순서입니다.**
- **KYNEX가 이미 다른 점:** 설치 없는 웹 뷰어, Kreate와의 실시간 공동 편집, 부품 5만 개
  규모 성능. 기능을 맞춘 뒤 VC에서 옮겨 올 이유가 되는 부분이라 계속 지킵니다.

## 3. 지킬 강점

기능을 맞추는 것만으로는 이미 VC를 쓰는 곳이 옮겨 오지 않습니다. 아래가 옮겨 올 이유입니다.

1. **설치 없는 웹 뷰어.** 현장 태블릿, 고객 회의실 PC, 사내망 어디서나 같은 화면을 봅니다.
   VC는 데스크톱 설치가 기본입니다. CNC 공장 현장에서 셀 계획을 바로 보여 줄 수 있습니다.
2. **Kreate와의 실시간 연결.** 모델링하는 사람과 시뮬레이션하는 사람이 같은 장면을 동시에
   봅니다. VC에는 이런 공동 편집이 없습니다.
3. **규모.** 부품 5만 개 장면을 브라우저에서 63 fps(전체 보기)로 보고, 충돌 검사도 로봇 주변만
   봅니다(`kynex bench`로 측정). 공장 전체를 한 장면에 두는 쓰임에서 유리합니다.
4. **열린 형식.** URDF를 그대로 씁니다. 로봇 모델을 ROS 생태계에서 바로 가져올 수 있습니다.
5. **AI 연동.** KYNEX에 MCP 도구를 두면 "CNC 두 대를 로봇 하나로 돌리는 셀을 만들어 줘" 같은
   작업을 AI에게 맡길 수 있습니다. VC가 아직 내세우지 않는 영역입니다.

## 4. 첫 대상: CNC 머신 텐딩 셀

M1 판정에 쓸 대표 셀입니다. 이 셀을 VC 없이 KYNEX만으로 설계·검증할 수 있으면 M1입니다.

**셀 구성**

- 6축 로봇 1대. 주행축(트랙) 위에 올려 CNC 여러 대를 맡는 변형도 포함.
- CNC 선반 또는 머시닝센터 1–3대: 자동문, 척(바이스), 가공 사이클.
- 소재 투입대: 격자로 놓인 소재 팔레트(또는 서랍).
- 완성품 배출대: 격자 팔레트 또는 배출 컨베이어.
- 그리퍼: 2지 그리퍼, 또는 소재·완성품을 한 번에 바꾸는 이중 그리퍼.
- 안전 펜스.

**기준 수치** (업계 일반 값으로 정함, 2026-10-14. 현장 값이 생기면 바꿉니다)

| 항목 | 값 | 근거 |
|---|---|---|
| 로봇 | UR10e (가반하중 12.5 kg, 도달 1,300 mm) | 그리퍼와 소재를 합쳐 5 kg 안팎이라 UR5e(5 kg)는 여유가 없음. 머신 텐딩 협동로봇에서 흔한 급 |
| CNC | 소형 CNC 선반 2대, 외형 약 1.8 × 1.6 × 1.9 m, 자동문 폭 약 0.6 m | 소형 부품 가공 셀의 일반적인 장비 |
| 가공 시간 | 90 s | 소형 선반 부품의 흔한 범위(60–180 s)의 가운데 |
| 자동문 | 열림·닫힘 각 3 s | 공압 자동문 |
| 척 | 열림·닫힘 각 1 s | 유압 척 |
| 소재 | Ø60 × 80 mm 강 환봉, 약 1.8 kg. 완성품 Ø55 × 75 mm | 소형 선반 가공품 |
| 그리퍼 | 공압 2지 이중 그리퍼, 개폐 0.5 s, 약 2.5 kg | 한 번 진입으로 소재·완성품 교체 |
| 투입·배출 팔레트 | 5 × 4 = 20칸, 간격 100 mm | Ø60 소재에 손가락이 들어갈 간격 |
| 로봇 속도 | 접근·후퇴 MoveL 250 mm/s, 이동 MoveJ 최고 속도의 60% | 협동로봇을 펜스 안에서 쓰는 일반 설정 |
| 안전 펜스 | 높이 2 m | 일반 산업용 펜스 |

**한 사이클**

1. 투입 팔레트의 다음 칸에서 소재를 집는다.
2. CNC가 "가공 완료·문 열림"을 알리면 문 안으로 들어가 완성품을 빼고 소재를 척에 넣는다
   (이중 그리퍼면 한 번의 진입으로 교체).
3. "척 닫힘"을 받고 물러나며 "가공 시작"을 보낸다.
4. 완성품을 배출 팔레트의 다음 칸에 놓는다.
5. 다음 CNC로, 또는 1로.

**KYNEX가 보여 줘야 하는 것**

- 사이클 전체가 신호로 맞물려 반복 재생됨.
- 로봇과 장비 문·척 사이 근접 거리와 충돌.
- 셀 사이클타임, 로봇 대기 시간, **CNC별 가동률**(가공 중인 시간 비율).
- 시나리오 비교: CNC 대수(1–3대), 이중 그리퍼 유무, 주행축 유무에 따른 가동률·처리량.
  머신 텐딩 투자 판단의 핵심 질문("로봇 한 대로 CNC 몇 대를 감당하나")에 답합니다.
- 로봇 프로그램 내보내기(첫 제조사는 UR, 7절).

| 1.6 | **프로그램 명령**: 디지털 출력, 입력 대기, 시간 대기, 그리퍼 열기·닫기, 반복, 서브루틴, 팔레트 다음 칸 | 신호로 장비와 맞물리려면 필요 | 중 |
| 1.7 | **신호와 인터록**: 로봇↔CNC 핸드셰이크, 장비 상태 표시 화면 | CNC 셀은 신호가 사이클을 결정 | 중 |
| 1.8 | **근접 거리(클리어런스) 검사**와 기준값 | 장비 문 안으로 들어가는 경로라 닿기 전에 경고해야 함 | 중 |
| 1.9 | **블렌딩 반경, 원호 이동(MoveC)** | 블렌딩이 없으면 사이클타임이 길게 나와 판단이 틀어짐 | 중 |
| 1.10 | **사용자 좌표계**: CNC별·팔레트별 좌표계 | 같은 동작을 CNC 여러 대에 재사용, 장비 위치가 바뀌어도 프로그램 유지 | 중 |
| 1.11 | **타임라인과 가동률**: 로봇·CNC별 작업·대기 간트 차트, CNC 가동률, 처리량 | 머신 텐딩 투자 판단의 핵심 수치 | 중 |
| 1.12 | **시나리오 비교**: CNC 대수, 그리퍼 종류, 주행축 유무를 바꿔 반복 실행하고 표로 비교 | "로봇 한 대로 몇 대"에 대한 답 | 중 |
| 1.13 | **URScript 확장과 URSim 검증**: 1.6 명령과 1.9 블렌딩까지 내보내고 URSim에서 실행 | UR은 머신 텐딩에 많이 쓰이고 무료 시뮬레이터가 있음 | 중 |
| 1.14 | **프로그램 여러 개, 이름·주석** | 메인과 서브루틴, CNC별 프로그램 | 소 |

완료 기준: 4절의 셀(CNC 2대, 이중 그리퍼)이 신호로 맞물려 30분 분량 반복 재생되고, CNC별
가동률과 셀 처리량이 나오며, 같은 셀의 URScript가 URSim에서 그대로 돈다. URSim에서 측정한 로봇
동작 시간이 KYNEX 계산과 10% 이내로 맞는다.

### 공통 기반(단계와 함께 진행)

- **공개 API:** 지금의 `POST /robot`를 정리해 문서화하고, Python 클라이언트와 MCP 도구를
  둡니다. VC는 Python 3 API를 강조합니다.
- **프로젝트 파일:** 셀 파일(1.1), 프로그램, 신호 매핑, 카탈로그 참조를 한 프로젝트로 묶습니다.
  지금은 `kynex-programs.json`만 있습니다.
- **증분 충돌 검사:** 장비 문과 부품이 계속 움직이면 지금 방식(5만 부품 장면에 28 ms)으로는
  부족합니다. 바뀐 물체만 갱신하도록 바꿉니다.

## 7. 포스트프로세서 검증 (유료 시뮬레이터 없이)

| 방법 | 쓰는 곳 |
|---|---|
| 제조사의 무료 시뮬레이터에서 실행 | UR(URSim, 무료). 다른 제조사도 무료 시뮬레이터나 체험판이 있는지 제조사별로 확인 |
| 기준 출력 비교 시험 | 모든 제조사. 같은 프로그램에서 나오는 코드를 저장해 두고, 바뀌면 시험이 실패하게 함. 제조사 매뉴얼의 문법·예제로 기준 출력을 만듦 |
| 실제 로봇 시험 | 무료 시뮬레이터가 없는 제조사. 고객사·협력사 현장에서 첫 실행을 함께 확인 |

**제조사 순서.** CNC 머신 텐딩에서 흔히 쓰는 제조사와 검증 수단이 있는 곳부터 갑니다.

1. Universal Robots: 머신 텐딩 협동로봇의 대표. URSim으로 검증(1단계).
2. FANUC: 공작기계 셀에서 가장 흔한 산업용 로봇. 무료 검증 수단이 없으면 기준 출력과 현장 시험.
3. 국내 협동로봇(두산로보틱스, 레인보우로보틱스)과 ABB, YASKAWA, KUKA: 무료 시뮬레이터 여부를
   확인해 검증 수단이 있는 곳부터.

## 8. Kreate 없이 KYNEX가 할 일

Kreate는 지금 기능 그대로 씁니다. 장면 모델링, URDF 가져오기, 공동 편집 세션이 그것입니다. 처음
안에서 Kreate에 맡겼던 일은 이렇게 바꿉니다.

| 처음 안 | 바뀐 방식 |
|---|---|
| 사용자 속성(K4)으로 컴포넌트 역할 정의 | KYNEX 셀 파일(1.1)에 역할·속성을 저장 |
| 연결점 스냅, 배치는 Kreate | KYNEX 안에서 카탈로그 배치(3.3) |
| 제조사 CAD(STEP) 가져오기로 카탈로그 확장 | 3단계에서 KYNEX가 직접 가져올지 결정. 그 전까지 Kreate 지금 기능으로 가져온 메시를 씀 |
| 제안용 고품질 렌더링(Kreate 렌더러) | 뷰어 화면 녹화(3.6)로 시작 |
| 뷰어에서 만든 자세를 Kreate로 보내기(K1, P2) | Kreate 쪽 진행에 맡김. 그 전까지 KYNEX에만 둠 |
| Kreate 고정 커밋 올리기 | 필요할 때만. Kreate 변경을 기다리지 않음 |

## 9. 하지 않을 것과 방식을 바꿀 것

- **카탈로그를 손으로 수천 종 만드는 일은 하지 않습니다.** CNC 셀에 쓰는 주력 기종부터 갖추고
  (3.1, 3.2), 나머지는 가져오기로 넓힙니다.
- **고품질 렌더링·VR은 경쟁하지 않습니다.** 뷰어는 빠르고 가벼운 쪽을 지킵니다.
- **물류는 별도 엔진으로 만들지 않습니다.** 셀 시뮬레이션 엔진을 넓힙니다.
- **유료 시뮬레이터는 쓰지 않습니다**(7절).

## 10. 대체 가능 판정 기준

단계가 끝날 때마다 VC의 어느 쓰임을 대신할 수 있는지로 진척을 판단합니다. 판정은 "VC로 하던
실제 프로젝트 하나를 KYNEX만으로 끝까지 해 본다"로 합니다.

| 이정표 | 끝난 단계 | 대체 대상 | 판정에 쓸 프로젝트 |
|---|---|---|---|
| M1 | 1단계 | VC로 하던 CNC 머신 텐딩 셀 검토 | 4절의 셀: CNC 2대, 이중 그리퍼, URScript를 URSim에서 실행 |
| M2 | 2, 3단계 | VC Robotics OLP, Essentials·Professional 사용자 | 카탈로그로 배치한 머신 텐딩 + 디버링 셀, 두 제조사로 내보내기, 제안 영상 |
| M3 | 4단계 | VC Premium 사용자 | M2 셀을 실제 PLC·CNC 신호와 연결해 가상 시운전 |
| M4 | 5단계 | 공장 계획 사용자 | CNC 셀 여러 개 + AGV 소재 이송: 처리량·병목 분석, 시나리오 비교 |

## 11. 남은 결정

1. **M1 셀의 기준 수치.** CNC 가공 시간, 문 개폐 시간, 소재 크기·무게 등 4절 셀의 대표 값을
   정합니다. 실제 현장 값이면 좋고, 없으면 업계 일반 값으로 시작합니다.
2. **가격·라이선스 위치.** 이 문서는 기능만 비교했습니다. VC 가격과 등급별 정확한 기능 구분은
   공개 자료에서 확인하지 못했습니다.
